## 当前实现信息

- 版本号以 `metadata.yaml` 的 `version` 为唯一事实源；逐版变更见 `CHANGELOG.md`。
- AstrBot 兼容范围:与 metadata.yaml 的 `astrbot_version` 一致的值(当前为 `>=4.16,<5`)。
- 命令入口:聊天命令 `/境`、`/境时间`、`/境日历`、`/境天气`、`/境空气`、`/境预警`;页面入口:插件详情中的 status 管理页。

## 简介与定位

为 AstrBot 提供按需的当地日历、天气、空气质量、官方气象预警与自然事件感知。按需工具只在模型实际调用时联网；设置常驻地点后，可由独立后台任务刷新一条环境关心候选，普通回复钩子只读缓存、不等待联网。公共假日或调休工作日可以在当地当天首次对话提供一条离线轻量事实，并明确要求模型只在自然相关时参考。

在凝心溯溪系列的职责划分中，境负责“外界现在怎样”（天气、日历、空气质量与官方预警），不负责身份、关系语气、主动发送与收件人权限；是否关心、表达语气和篇幅由当前人格、关系与对话上下文决定。

主要特点：

- 开箱即用：Open-Meteo、中央气象台公开预警列表、USGS 和 python-holidays 均不要求 API Key。
- 单用户只需一个地点：插件页面的常驻城市是全局配置，不按用户隔离；多用户部署应在每次查询中显式提供地点。
- 模型自主决定：注册语义清晰的只读工具，不增加一次“要不要查询”的 LLM 请求，不使用关键词硬路由。
- 后台关心候选：设置常驻地点后定时刷新环境数据，只缓存一条达到阈值的结构化事实；普通回复不等待联网，旧候选不会发起新的关心。
- 现实日历：区分公共假日、普通周末和调休工作日；不把中国周末简单等同于休息日。
- 环境细节：提供 AQI、颗粒物、紫外线、可用花粉、日出日落、白昼长度、能见度和未来约 6 小时的 15 分钟降水模型数据。
- 预警分源：中央气象台官方预警与 Open-Meteo 阈值风险信号使用独立字段和标签，不互相冒充。
- 本地相关性过滤：距离过远、震级不足或预计基本无影响的地震不会返回给模型。
- 不误报无风险：数据源失败与“已查询但没有相关事件”是两种不同状态。
- 隐私克制：经纬度不进入工具公共结果，远处事件的详情和数量也不进入模型上下文。
- 常驻管理页：可分组编辑公开配置、查看调用统计与最近记录，并在浏览器授权后使用当前设备位置快速设置常驻地点。
- 更新健康检查：声明 `plugin.health@1.0`，供凝心溯溪-核在更新后验证 HTTP 会话与六个工具是否就绪；未配置可选常驻地点不视为故障。

## 功能

### LLM 工具一览

| 工具 | 用途 |
|---|---|
| `get_local_datetime` | 查询地点当前日期、时间、星期和时区 |
| `get_local_calendar` | 查询公共假日、周末、调休工作日和下一个节假日 |
| `get_weather` | 查询当前、未来约 6 小时 15 分钟降水、未来 24 小时或 1-7 日天气 |
| `get_air_quality` | 查询 AQI、污染物、紫外线和可用花粉数据 |
| `get_environment_alerts` | 查询本地官方气象预警、强天气模型信号与相关地震 |
| `list_environment_locations` | 检查常驻地点是否已配置 |

### 节假日与调休

节假日由 `python-holidays` 离线计算。中国日历会使用库中已收录的年度官方放假安排区分法定假日和周末补班；例如 `2026-02-17` 是春节休息日，而 `2026-02-14` 是调休工作日。

- 城市查询自动使用地点的 ISO 国家代码。
- 纯经纬度无法确认国家时，可设置 `calendar_country_code`。
- 部分国家的地方性假日可通过 `holiday_subdivision` 指定。
- 尚未公布或尚未被依赖库收录的未来调休不会被猜测；应更新依赖或等待正式安排。

### 空气质量、日照与短临天气

- 空气质量来自 Open-Meteo CAMS 模型，包括 European AQI、US AQI、PM2.5、PM10、气态污染物、UV 和当前地区可用的花粉数据。
- 花粉字段在许多地区可能为空；插件会明确返回不可用，不补造数值。
- 当前天气结果附带当日日出、日落、白昼长度和能见度。
- `nowcast` 返回未来 24 个 15 分钟间隔，即约 6 小时的降水模型序列与摘要。它不是气象雷达临近预警。

这些数据用于环境感知，不替代当地空气监测、医疗建议或防晒指导。

### 中央气象台官方预警

中国地点启用 `official_weather_warnings_enabled` 后，插件查询中央气象台当前预警公开列表：

1. 根据地点解析得到省级行政区，只查询对应省份。
2. 对城市和区县再次匹配发布机构；同省其它城市的预警不会返回。
3. 省级气象台发布的预警视为省域相关，并标记 `scope=province`。
4. 缺少发布时间、标题结构异常、超过 `official_warning_max_age_hours` 或未来时间异常的记录会被过滤。

非中国地点返回 `official_warning_status=unsupported_region`，不把“不支持”描述成“没有预警”。使用纯经纬度时可设置 `official_warning_province`，但缺少城市信息时只保留省级发布的预警。该公开接口不可用时会返回 `unavailable`，Open-Meteo 模型风险信号仍保持独立结果。

### 地震相关性过滤

地震必须同时满足：

1. 不低于 `earthquake_min_magnitude`。
2. 不超过管理员设置的 `earthquake_max_distance_km`。
3. 震中距与深度合成后的有效距离，不超过震级对应的感知半径。

默认震级半径：

| 震级 | 半径上限 |
|---:|---:|
| `< 3.0` | 15 km |
| `3.0-3.9` | 40 km |
| `4.0-4.9` | 100 km |
| `5.0-5.9` | 250 km |
| `6.0-6.9` | 600 km |
| `7.0-7.9` | 1200 km |
| `>= 8.0` | 2500 km，但仍受绝对最远距离限制 |

达到最低震级且处于 `earthquake_nearby_radius_km` 内的近场事件会保留。带海啸标记的强震可以使用单独半径，但同样不能突破绝对最远距离。

这是一套保守的“是否值得感知”启发式算法，不是烈度预测。返回内容会明确保留该限制。

### 本地天气风险信号

Open-Meteo 不提供中国官方预警。插件只把当地模型预报达到以下阈值的结果称为“风险信号”，并与中央气象台官方预警分栏：

- 日累计降水默认 `50 mm`
- 阵风默认 `62 km/h`
- 最高温默认 `40°C`
- 最低温默认 `-20°C`
- WMO 雷暴代码 `95/96/99`

所有阈值均可调整。风险信号不会冒充气象部门发布的预警。

### 环境关心候选与主动消息

`opportunity_cache_enabled=true` 且已设置常驻地点时，境在后台并行读取预警、天气和空气质量缓存，从黄色及以上官方预警、高 AQI/UV、强天气、相关地震或强降温中选出严重度最高的一条。候选使用 `environment.opportunity@1.0`，只包含稳定事件键、修订哈希、严重度、有效期、来源和结构化事实，不含成品话术、UID、自然人 ID、UMO 或好感度。同一事件的实时数值变化不会改变事件键；主动发送后，或模型已经判断同严重度不值得发送后，只有严重度升级才会再次判断。未发送的判断不计入每日发送额度。

普通回复只读取新鲜候选，不同步联网，也不要求模型提及。候选仅在当前私聊同时通过以下校验时交给主模型一次：

1. 境的 `care_person_id` 与 `care_recipient_umo` 已配置，且当前 UMO 精确匹配。
2. 序通过 `identity.proactive_authorization@1` 确认该完整 UMO 在主人私聊白名单中。
3. 情通过 `relationship.delivery_identity@1` 确认该 UMO 属于该自然人，并提供不含原始分数的关系语气建议。
4. 言通过 `conversation.proactive_delivery@1` 决定是否自然引入；不相关时模型直接忽略。

真正主动消息还必须显式开启 `proactive_enabled`，并通过安静时段、最低严重度、跨重启事件去重和每日上限。境只触发言的公开交付契约，不直接调用平台发送接口；言会再次校验序与情，让对话模型决定是否值得发和最终措辞。任一插件缺失、契约不兼容、群聊目标、未绑定账号、未授权目标、旧候选或模型选择不发时均严格停止，不降级为直发。`proactive_paused` 可随时暂停发送而保留后台刷新。

### 数据源

- [Open-Meteo Weather Forecast API](https://open-meteo.com/en/docs)：地点解析、当前天气、逐小时与逐日模型预报。
- [Open-Meteo Air Quality API](https://open-meteo.com/en/docs/air-quality-api)：空气质量、紫外线和可用花粉模型数据。
- [Open-Meteo Geocoding API](https://open-meteo.com/en/docs/geocoding-api)：城市名解析与时区。
- [中央气象台预警信息](https://www.nmc.cn/publish/alarm.html)：中国当前官方气象预警公开列表。
- [USGS Earthquake GeoJSON Feed](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php)：全球地震结构化数据。
- [python-holidays](https://python-holidays.readthedocs.io/)：离线公共假日、工作日和已收录调休规则。

USGS 对不同地区、不同震级的收录完整性可能不同。插件不能替代中国地震台网、中国气象局、当地应急部门或其它正式信息渠道。

## 安装

1. 通过 AstrBot 插件市场或仓库地址安装插件并重载。
2. 打开插件详情中的“status”页面。
3. 在“常驻地点”填写城市，例如 `杭州` 或 `广东省珠海市`，点击“保存并校验”；也可点击“使用当前设备位置”授权定位并直接校验保存。
4. 点击“测试数据源”确认日历、天气、空气质量、官方预警与本地相关性过滤可用。

没有设置常驻地点时也可以直接询问“上海现在天气怎么样”，模型会把上海作为临时地点传给工具。

### 依赖

第三方依赖登记在 `requirements.txt`，安装插件时由 AstrBot 自动安装，也可手动执行 `pip install -r requirements.txt`：

- `httpx>=0.27.0`：异步 HTTP 客户端，访问各数据源。
- `holidays>=0.101,<1`：即 python-holidays，离线公共假日与调休计算。
- `tzdata>=2024.1`：仅 Windows 平台需要，提供时区数据库。

无需注册天气账号，无需配置密钥：Open-Meteo、中央气象台公开预警列表、USGS 和 python-holidays 均不要求 API Key。

真正主动消息默认关闭；保存地点且开启默认的候选缓存后，后台会按间隔刷新环境数据，但普通回复不会等待这些请求。插件配置中会保留一份地点解析缓存，用于避免每次先定位；经纬度不会进入 LLM 工具或候选的公共结果。

## 配置

完整配置项与取值范围以 `_conf_schema.json` 为准；主要配置如下。

| 配置 | 默认值 | 说明 |
|---|---:|---|
| `default_location` | 空 | 插件级全局常驻城市或经度,纬度；不按用户隔离，多用户部署应显式传地点 |
| `forecast_days` | 3 | 默认逐日预报天数，范围 1-7 |
| `calendar_awareness_enabled` | true | 重要节假日/调休在当地当天首次轻量感知 |
| `calendar_country_code` | 空 | 节假日 ISO 国家代码手动覆盖 |
| `holiday_subdivision` | 空 | 可选地方节假日行政区代码 |
| `official_weather_warnings_enabled` | true | 是否查询中央气象台当前预警 |
| `official_warning_max_age_hours` | 72 | 官方预警最大发布时长 |
| `official_warning_province` | 空 | 省级地区手动覆盖 |
| `earthquake_min_magnitude` | 2.5 | 进入相关性判断的最低震级 |
| `earthquake_max_distance_km` | 1200 | 任何地震都不能突破的最远距离 |
| `earthquake_nearby_radius_km` | 30 | 近场关注半径 |
| `max_hazard_events` | 5 | 单次最多返回事件数 |
| `weather_risk_enabled` | true | 是否计算本地天气模型风险信号 |
| `opportunity_cache_enabled` | true | 设置常驻地点后在后台刷新一条环境关心候选；回复钩子只读缓存 |
| `opportunity_refresh_seconds` | 900 | 后台刷新间隔，范围 300-21600 秒 |
| `opportunity_min_severity` | medium | 候选最低严重度；默认忽略蓝色预警等低级信号 |
| `care_person_id` | 空 | 情的账号归属页中已确认的自然人 ID |
| `care_recipient_umo` | 空 | `/sid` 给出的完整私聊 UMO，且必须在序中另行授权 |
| `proactive_enabled` | false | 真正主动发送总开关 |
| `proactive_paused` | false | 暂停主动发送但保留后台候选 |
| `proactive_min_severity` | high | 主动发送最低严重度 |
| `proactive_quiet_start` / `proactive_quiet_end` | 23:00 / 07:00 | 常驻地点当地安静时段 |
| `proactive_daily_limit` | 1 | 当地日期内主动环境关心上限 |
| `air_quality_ttl_seconds` | 1800 | 空气质量缓存时间 |
| `request_timeout_seconds` | 6 | 单次数据源请求超时 |
| `stale_cache_seconds` | 3600 | 故障时允许使用的旧缓存时长 |

旧缓存会带 `stale=true`，不会伪装成实时结果。后台刷新失败时仍可保留旧数据供显式查询降级，但旧候选不会触发新的回复注入或主动消息。某个来源暂时失败时，它仍在有效期内的候选不会被其它来源的空结果误清；候选到期后会自然停止使用。关闭候选缓存且主动发送也关闭时，后台任务会退出；切换常驻地点会立即丢弃旧地点候选。

## 使用

### 聊天命令

```text
/境
/境时间 [地点]
/境日历 [地点] [YYYY-MM-DD]
/境天气 [地点] [current|nowcast|hourly|daily]
/境空气 [地点] [预报小时数]
/境预警 [地点] [回看小时数]
```

示例：

```text
/境天气 杭州
/境天气 杭州 nowcast
/境天气 上海 daily
/境日历 杭州 2026-02-14
/境空气 杭州 12
/境预警 成都 24
```

### LLM 工具与模型行为

工具说明既覆盖直接实时事实查询，也覆盖现实数据会改变决定的隐式语境。直接询问“今天多少度”“现在天气如何”“最近有下雨吗”或未来天气属于明确的实时事实请求，即使没有穿衣、通勤等决策场景，也应调用 `get_weather`，而不是按普通闲聊直接猜测或等待用户自己报告天气。跨时区联系、约见与出行安排、通勤、穿衣带伞、晾晒、户外运动、开窗、防晒、过敏暴露和附近震感等场景仍按实际需要选择对应工具。模型在当前回复中自主判断，不增加额外 LLM 请求，也不使用关键词硬路由；选择最小够用的查询范围，获取数据后只使用与当前问题直接相关的信息，不扩展无关环境内容或强行转题。是否关心、表达语气和篇幅继续由当前人格、关系与对话上下文决定，境不单独覆盖这些约束。

`default_location` 是插件级全局地点：单用户部署且已配置有效常驻地点时，可用它回答“你那今天多少度”“你那里天气如何”“你那边最近有下雨吗”，模型直接让 `location` 留空调用。单用户部署查询天气、空气或风险时，模型应直接调用目标工具并可让 `location` 留空使用全局常驻地点，不先调用 `list_environment_locations`。多用户部署不能据此区分不同用户，必须传入当前用户明确给出的地点；地点归属不明或没有有效常驻地点时，应先自然追问地点，不得编造地点或天气，不得把全局地点当成当前用户地点。地点列表工具仅用于管理员排查配置，不能作为用户身份识别手段。

普通问候、仅提到出门或上班、节日文化历史、文学比喻、虚构天气、天气回忆、纯情绪化的“心里阴天”、只描述症状、影视游戏中的灾害以及与地点无关的新闻，不会因为出现相似词语就要求调用工具。插件不会把天气塞进每轮 system prompt。`calendar_awareness_enabled=true` 时，只有公共假日或调休工作日会在当地当天首次 LLM 请求加入一条短公共日历事实；模型可在确有帮助时作一句简短节日问候或调休关心，否则必须忽略，不得据此断言用户本人一定放假或上班。普通日期、同日后续对话和未校验地点均不注入，也不会为该轻量感知发起网络请求。

模型路由的预期示例：

| 用户表达 | 预期工具 |
|---|---|
| “杭州今天多少度 / 现在天气怎么样” | `get_weather`，使用 `current` |
| “你那今天多少度 / 你那边最近有下雨吗”（单用户且已配置常驻地点） | `get_weather`，`location` 留空，按问题使用 `current` 或 `nowcast` |
| “你那边天气如何”（地点归属不明或没有有效常驻地点） | 先自然追问地点，不编造、不等待用户自己报告天气 |
| “半小时后骑车，要带雨衣吗” | `get_weather`，优先 `nowcast` |
| “后天去西湖，穿薄外套够吗” | `get_weather`，使用 `daily` |
| “今晚跑步，我对花粉敏感” | `get_air_quality`，天气按实际需要可选 |
| “刚才杭州好像晃了一下” | `get_environment_alerts` |
| “明天调休算工作日吗” | `get_local_calendar` |
| “伦敦现在几点，适合联系吗” | `get_local_datetime` |
| “早上好 / 我出门上班啦 / 回忆去年暴雨 / 写一段暴雨小说 / 我心里像阴天” | 不调用环境工具 |

### 插件管理页（Plugin Page）

管理页常驻可用，并采用与“情”“核”一致的系列视觉与“总览 / 配置 / 实时检查”页签导航。AstrBot 的 Plugin Page 入口由插件内静态页面决定，运行时配置无法可靠地动态隐藏入口，因此不再提供无效的页面显示开关。页面可完成以下操作：

- 按基础、日历预警、环境关心、主动关心、风险阈值和缓存分组编辑 `_conf_schema.json` 中的公开配置，并立即校验数值范围。
- 页面会同时读取运行状态和配置，减少打开时的等待；下拉选项优先显示中文。配置读取失败会在页面顶部直接提示，不会只藏在配置页签里。
- 数字项留空、填入非数字或超出允许范围时会指出具体哪一项有问题，不会悄悄改回默认值后继续保存。
- 查看命令、LLM 工具、实际发生的轻量感知和主动关心交付的累计次数及最近 12 次记录。页面刷新和“测试数据源”不会计入真实调用次数。
- 调用统计跨重启保存在插件数据目录，只记录时间、入口、功能、结果和耗时；不记录消息内容、用户 ID、UMO 或查询地点。
- “使用当前设备位置”由浏览器在用户点击后请求系统定位权限，得到的坐标会直接校验并保存为常驻地点。浏览器通常只允许在 HTTPS 或 `localhost` 页面使用定位；插件不会静默定位。

常驻地点仍使用独立的“保存并校验”接口，不能通过通用配置表单绕过地点解析。页面保存其它参数后会热应用；无需重启。

中文地点会先尝试原始输入；完整行政区名称无结果时，再按区县、城市、省份逐级回退，并使用父级行政区校验同名结果。对 `珠海` 这类被数据源优先匹配到同名小地点的输入，还会在低质量结果后尝试 `珠海市`，不会简单统一删除或追加行政区后缀。

## 兼容性

- AstrBot 版本：与 `metadata.yaml` 的 `astrbot_version` 一致，当前为 `>=4.16,<5`。
- 除上述版本约束外，未另行登记平台级兼容限制。

## 已知限制

- 真正主动消息默认关闭；即使开启也只向序明确授权且由情确认归属的私聊 UMO 发送。
- 已接入中央气象台当前气象预警公开列表；暂未接入中国地震速报和海啸预警接口。
- 官方预警目前只支持能确定中国省级行政区的地点，不使用 IP 猜测位置。
- 不推测用户位置，不从聊天内容静默保存住址。
- `default_location` 是插件级全局配置，不代表当前发言者的位置；跨平台人物绑定只用于校验一个明确关心对象，不会自动为不同用户分配地点。
- 不把天气和灾害事件写入“知”的长期记忆。
- 不读取 UID 或“情”的原始好感值，也不因关系高低改变环境严重度；只由言消费情给出的派生语气与主动性建议。

## 系列诊断日志

本插件声明 `series.diagnostics@1.0` 诊断接口，在内存中保留有界的运行事件，供凝心溯溪-核统一查看。

- 契约同时声明系列 ID、插件 ID、中文简称、内存存储及读取/清空能力；仓库元数据匹配后由“核”自动发现，不需要修改“核”。
- 诊断会捕获本插件自有 logger 的 `DEBUG` 到 `CRITICAL` 事件；只保留启动状态、明确标记的关键运行节点和异常告警等真正有检修价值的事件，不把每次普通环境查询都写成流水账。
- 内存缓冲最多保留 1000 条，日志页单次最多读取 1000 条、浏览器最多暂存 10000 条；每条记录由“核”先显示插件中文名，再显示时间、级别和事件。
- 自动捕获事件会保留模块、函数、行号、异常类型，以及最长 2000 字符的脱敏日志正文；在“核”的日志页点击事件即可展开。
- 诊断通道只读取本插件自身日志，不读取或输出 AstrBot 全局日志；写入前会自动脱敏敏感标识并截断过长内容。插件不会额外读取聊天消息，但若本插件原有日志本身含有用户文本片段，该片段会在脱敏、截断后进入内存详情。
- 记录只存在内存中，插件重载或 AstrBot 重启后会自动清空；清空或热重载会更换流标识。
- 没有安装或没有运行“核”时，天气、预警、空气质量和环境关心候选等功能照常工作。

## 系列控制

境提供 `series.control@1.0`，供凝心溯溪-核统一管理少量非秘密运行开关。可接管字段只有三个：`proactive_enabled`、`opportunity_cache_enabled` 和 `opportunity_refresh_seconds`（300-21600 秒）；常驻地点、关心对象、各类阈值和缓存时间等其余配置不属于该契约，契约响应也不包含秘密字段。

核可以读取契约与快照、校验并应用补丁、重置覆盖，以及切换 native/managed 接管模式；补丁按 revision 乐观校验，冲突时拒绝而不强行覆盖。覆盖快照由境在插件数据目录原子保存；managed 模式下覆盖立即热生效、无需重启，关闭接管后回退插件原生配置。核未安装或不可用时，境照常使用自身配置运行。
